# Navigate the wiki

The wiki is already structured and already linked. Do not treat it as a pile of
documents to grep at random, and do not read pages whole "to be safe" — the page
set is known, the graph is written down, and reading the wrong page costs the
same as reading the right one.

Work from the outside in. Each step below is cheaper than the one after it, so
stop as soon as you have the answer.

## The four tools

All are POSIX sh, run from the project root, and need nothing installed:

```sh
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-search.sh"  <query> [--feature f] [--page p] [--status s] [--kind k] [--paths-only]
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-outline.sh" <page>
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-section.sh" <page> <heading>
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh"   --backlinks <name>
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh"   --synonyms <term>
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh"   --mentions [--all]
```

`<page>` is a path **or** a link name **or** an alias — `checkout`,
`checkout-validations`, `ADR-0007`, and
`business-docs/wiki/features/checkout/validations.md` all work.

## The order

1. **`wiki-search.sh <query>`** — one pass. It reports an *exact name match*
   first when the query is a link name, alias, or page title; that block is a
   deterministic hit, not a ranked guess, and it is usually the whole answer.
   Narrow with the filters rather than with a cleverer query: `--feature
   checkout`, `--page validations`, `--kind decision`, `--status stub`.
2. **`wiki-outline.sh <page>`** — frontmatter, the heading outline with line
   numbers, links out, and backlinks. About 5% of the page. Read this before
   opening any wiki page, to confirm it is the right one and to pick the
   section.
3. **`wiki-section.sh <page> <heading>`** — only that section, down to the next
   heading of the same or a higher level. This is the normal way to read the
   wiki.
4. **Read the whole file** only when you are about to *edit* it, or when the
   outline shows it is short and you need all of it.

## The glossary is the synonym table

`wiki-search.sh` expands a query through the glossary automatically: search the
wire name and you also get the database column and the client field, because the
glossary lists all three for one concept. It says so in its output when it does.
Pass `--no-synonyms` to turn it off.

This is the deterministic answer to the one thing an embedding would buy here —
and it only expands to *specific* forms (phrases, dotted or underscored names,
camelCase). Expanding to a bare word like "question" took one real query from 4
matches to 779.

If a search comes back empty, check whether the term is in the glossary under
another name before concluding the wiki does not cover it.

## Backlinks are the change-impact question

Before changing a rule, ask what depends on it:

```sh
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh" --backlinks checkout-validations
```

Every page listed states or relies on something you are about to move. This is
the one question a plain search cannot answer, and skipping it is how a wiki
develops contradictions.

## Where the index comes from

`business-docs/index.tsv` — derived from the wiki, one row per page:

```
link_name  path  kind  feature  page  status  updated  title  aliases  links_out
```

It is regenerated by the `PostToolUse` hook on every wiki edit made in a
session, so it is normally current. It is **derived**: never hand-edit it.

Nothing rebuilds it automatically outside a session, so after a `git pull`, a
page edited in an editor, or a fresh install, check it before trusting a
backlink:

```sh
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh" --check   # stale? it says so
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh" --write   # rebuild
```

## Where the graph is thinner than the wiki

```sh
sh "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-index.sh" --mentions
```

Pages that name another page in prose without linking to it, most-mentioned
target first. Each one is an edge the writer meant and did not draw. Adding the
link makes it visible to `--backlinks`, which is what makes change-impact
answerable. `--all` also lists `ADR-NNNN` citations in prose, which are a
convention of their own and are excluded by default.

## What not to do

- Do not `cat` a feature's ten pages to "get context". Search, outline, section.
- Do not build a summary of the wiki into your own notes and then trust it. The
  wiki is the source; re-read the section.
- Do not add embeddings, a vector store, or a second index. At this corpus size
  the lexical index plus the link graph is both faster and exact, and a second
  index is one more thing that can silently go stale.
